# B0: The Tape never drops an accepted event silently

Mode: C · Writer: top agent · Depends on: none

## Current behavior
Observed: a 30-minute smoke logged `tape.dropped: 1540`. `Tape.flush` in `services/core/src/tape/tape.ts` gives up after four failed writes and counts the batch as dropped; listener callbacks run in `write()` after the transaction, so a listener error also fails the flush.

## Required behavior
A failed batch stays queued and is retried; while it cannot be written the process reports unhealthy (stats and `ops.alert`); a listener error after commit never re-runs or drops the write; `emit` and `emitIn` dedupe semantics are written in the file header.

## Invariants
The Tape stays append-only; dedupe keys keep a retried batch from writing twice.
