# D2: A run over its USD cap stops and is marked truncated

Mode: C (money spent on model calls, worker and Bridge) · Writer: top agent, or a subagent for the two Python workers · Depends on: D5 (both edit `bridge.ts`) · PLAN row: D2

## Current behavior
- observed: the Bridge records cost only after a run ends: `finish(..., cost_usd: s.output?.cost_usd ?? 0)` (`services/slow-bridge/src/bridge.ts:117`). Nothing stops a run on spend.
- observed: MiroShark reports `"usd": 0.0` hard-coded (`services/miroshark/engine/backend/asimog_worker.py:379`); its truncation is by time only (`SWARM_TIMEOUT_S`, lines 229-264).
- observed: no `SLOW_STAGE1/2/3_USD_PER_RUN` or `SLOW_USD_PER_DAY` exists (`.env.example`); the only limits are per-hour quotas (`bridge.ts:47-50`).
- suspected: BettaFish's `cost_usd` is not computed from token usage; confirm in `services/bettafish/engine/asimog_worker.py`.

## Required behavior
1. **Engines report real cost.** Each worker sums the cost from each model response's token usage times a price per 1k tokens taken from `config/models.json` (or env, if `models.json` is not built yet; never hard-coded). The cost appears on every status poll as `cost_usd`, not only at the end.
2. **Per-run cap.** The Bridge passes `usd_cap` (the stage's `SLOW_STAGE<n>_USD_PER_RUN`) in the start request. The worker checks spend before each model call. Once over the cap, it stops, returns what it has, and sets `truncated: true`.
3. **Per-day cap.** Before claiming a job, the Bridge sums `slow.jobs.cost_usd` for the day (UTC, by the job slot) and per lane. At or past `SLOW_USD_PER_DAY`, the job is marked `deferred` with the reason `day_cap`, never run.
4. **Recorded per lane.** `slow.jobs.cost_usd` holds the real cost; `ctl slow` prints today's spend per engine and stage.
5. A truncated swarm's samples are excluded from means (D5 owns that in the mapper; here, the worker just marks each sample).

## Invariants
Caps only stop work, never start it. Keys stay in `.env.local`. The lane keys' own provider limits remain the hard stop. No new dependency.
