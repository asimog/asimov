## Required behavior
- **Sources** come from `config/feeds.json`, each with its own cursor in `tape.feed_cursors`, and only those our own research documents: `recent` (`/home-feed/new`, as now), `hot` (`/home-feed`, ranked) and `follow` (the NATS `followingFeed` subject, plus B4's wallets). `trending` and `top_traders` are left out until we have recorded their endpoint and shape ourselves; nothing is taken from the upstream repos for sources.
- **Every chain is read; config picks what is stored.** Sources keep `chain=all`, so the reader sees every chain pump.fun carries (measured: `solana`, `base`, `robinhood`). `config/filters.json` `callout.chains` (now `["solana"]`) decides which are stored. Rejected callouts are counted per chain as well as per reason, so the owner can see what another chain would add before turning it on.
- **No assumed chain.** The NATS push path writes `chain: "solana"` for every item (`feed-reader.ts:288`) because the `followingFeed` payload has no chain field. Record a `followingFeed` slice in step 0: if it carries a chain, use it; if not, the item's chain is `null`, and `config/filters.json` `callout.unknown_chain` (`pass` or `refuse`) decides it. No chain is guessed from the shape of the mint.
- **Filters are config, not code.** A pure `passes(callout, filters)` in `services/core/src/senses/filters.ts` checks chain, minimum position in USD and market cap at call against `config/filters.json` `callout`, before the callout is written. Every threshold lives in that file; `filters.ts` holds no number. Changing a threshold is an edit and a restart; the new values are on the Tape as `config.loaded`. Adding a filter field is a schema line in `config.ts` and a key in the file, nothing else.
- **Rejected callouts** are counted per reason in stats, and `FILTER_SAMPLE_PCT` of them are written as `filter.sampled` (reason, source, callout). Sampling is by a hash of the callout id, so a second run samples the same ones.
- **A refused source is skipped, never worked around.** The hot feed answers Node with a Cloudflare challenge (403, `cf-mitigated: challenge`, measured 2026-10-19). A challenge or a 429 skips that source for that poll and is counted (`refused` with the status); the reader tries again on its next poll with its usual backoff. No other client, headers or tools to get past the check (owner decision 2026-10-19).

## Invariants
Filters drop only at the door; nothing already on the Tape is removed. `via: history` callouts pass the same filters. A source or a chain value is added only after we fetched it ourselves and recorded it in `docs/research/`; never guessed, never copied from another repo. Every source keeps the Feed Reader's backoff and `Retry-After` handling, and a refused source is skipped for that poll and counted, not retried in a loop. Filters run in the live senses only: a replay reads the callouts the Tape holds.
