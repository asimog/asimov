## Current behavior
Observed: the Scout promotes on `caller_buy`, `smart_buy`, `heat` or `metrics` (`services/core/src/senses/scout.ts:169`) with no launch check. Blocklists exist only in the Risk Gate (`services/core/src/mind/risk.ts:99-101`), so a blocked creator's coin is still watched, stored and backfilled.

## Required behavior
Before `coin.watched` (`scout.ts:179`), the launch features (dev buy SOL, block-0 sniper share, bundle share) are checked against `config/filters.json` `launch`, and creator, mint and trigger wallet against the owner lists (`blocked_creators`, `blocked_mints`, `blocked_wallets`, as of now). A refused launch is counted per reason and sampled as `filter.sampled`. Its trades still fold into the Index rollups.

## Invariants
The deny list is the owner's existing `blocked_wallets` and `blocked_creators` (known bad deployers and traders); the door checks both the creator and the trigger wallet. The list is loaded only by `ctl lists load`; no code adds to it (owner decision 2026-10-19).
The Risk Gate keeps its own blocklist check: the door adds a wall, it does not replace one. The filter uses only features known at the trigger trade (no lookahead).
