# E9: the fast suites pass on fresh databases

Mode: A · Writer: top agent · Depends on: none · PLAN row: E9

## Current behavior
- observed: `agent-lanes` "Ops finds a stalled tape" fails with "0 alerts, 0 stop requests" when run past minute 10 of an hour. The suite writes a raw row at now - 10 min straight into `tape.events` (`tests/e2e/suites/agent-lanes/suite.ts`) before that hour's partition exists, so the row lands in `tape.events_default`. The Tape then cannot create the hour ("updated partition constraint for default partition would be violated"), every flush fails, and the Ops alert never lands.
- observed: `Tape.emitIn` (`services/core/src/tape/tape.ts`) writes a decision inside a consumer transaction without making its hour partition; only `flush` made partitions. In a fresh database a decision written before the first flush of its hour goes to the default partition, with the same error after.
- observed: `npm run pg:start` fails unless `BETTAFISH_WORKER_TOKEN`, `SWARM_WORKER_TOKEN` and `NEO4J_PASSWORD` are set: compose interpolates every service, including profiled ones, with `:?`.
- observed: `slow-views` uses the working database, which predates hourly partitions ("events_default is not partitioned").

## Required behavior
- Every Tape write path makes the hour partition before the row: `flush` (already) and `emitIn` (inside the transaction, not cached, since a rollback undoes it).
- A test that writes raw rows makes their hour partition first.
- `pg:start` works with an empty `.env.local`; the workers still refuse to boot without their tokens (`REQUIRED` in each `asimog_worker.py`), Neo4j refuses an empty password.
- `slow-views` runs on its own fresh database with one seeded callout, so the `slow.as_of` check always runs.
